## Steps

1. Receive 5 of a SKU
2. Reserve 1 of it with key K
3. Send two POST /dispatches with key K and the same reservationId at the same time
4. Read the two answers and the stock

## What differs

```text
Expected: one tracking number for key K, one carrier booking
Actual: both answers 201 with different tracking numbers (run 1: T-1 and T-2; run 2: T-3 and T-4); the carrier stand-in booked two parcels for r-1 and r-2; stock ends at onHand 4, held 0
Seen: 2 of 2
Where it probably comes from: services/dispatch/src/dispatcher.ts, Dispatcher.dispatch: the `known` and `booked` checks run before the `await` on reservation() and book(), so two calls in flight both pass them and both book (guess: the in-flight calls need a per-reservation lock or a stored promise)
A test that would catch it: a dispatch test that sends two concurrent POST /dispatches with one key and one reservation, and asserts one tracking number and one carrier booking; the existing 'books once for a repeated key' test is sequential
```
